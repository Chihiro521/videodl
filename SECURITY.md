# Security Policy

## Supported Versions

Security reports are assessed against the current `desktop` branch.

Please include the affected release, tag, or commit when reporting an issue. Older releases are not guaranteed to receive security fixes; fixes will be prioritized for the current development branch.

## Reporting a Vulnerability

Please do **not** disclose vulnerability details in a public issue, pull request, or discussion.

The repository's GitHub private vulnerability reporting feature is not currently enabled. Until it is enabled, please contact the maintainer privately through the GitHub profile:

- https://github.com/Chihiro521

Please include as much of the following information as you can:

- A short description of the vulnerability and its potential impact.
- The affected version, tag, or commit.
- Steps to reproduce the issue.
- A proof of concept or relevant logs, with credentials and personal data removed.
- Any suggested mitigation, if known.

Do not include live API keys, access tokens, passwords, session cookies, or other secrets in a report.

Please allow the maintainer reasonable time to investigate and coordinate a fix before making the details public. There is no guaranteed response or remediation timeframe.

## Scope

Reports are especially relevant to code maintained in this repository, including the desktop application, its packaging and release scripts, and repository-maintained automation.

If a report concerns code inherited from an upstream project or a third-party dependency, please identify the affected component and version so it can be routed appropriately.
