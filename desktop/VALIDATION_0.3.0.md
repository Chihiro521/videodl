# v0.3.0 验证记录

## 性能比较

Windows 11 x64，本机 HTTP 服务提供同一份 11,363 字节 MP4；以独立数据目录启动 v0.2.0 与 v0.3.0，交替运行三轮“GUI 提取 → 选择视频 → 下载 → 退出”。子进程 PATH 仅包含 Windows System32，依赖发行包内的运行时与媒体工具。

| 轮次 | v0.2.0 | v0.3.0 |
| --- | --- | --- |
| 1 | 5.220 秒 | 2.974 秒 |
| 2 | 3.568 秒 | 2.376 秒 |
| 3 | 3.269 秒 | 2.356 秒 |
| 中位数 | 3.568 秒 | 2.376 秒 |

该固定场景的中位耗时减少 33.4%。三次新版下载均命中同一后台进程的解析缓存。新版额外探测实际分辨率，因此本场景的媒体 GET 次数从一次变为两次；主要提速来自复用进程与解析对象。网络平台耗时还受来源响应与媒体大小影响。

复测工具：`python -m desktop.benchmark --help`。原始记录存放在运行者指定的输出目录，不收录用户链接及本地运行记录到发行包。

## 功能验证

- 测试媒体包含实际 HLS 与 DASH 多档清单。分别选择低档下载，并用 FFprobe 确认文件为 320×180、包含音轨，保存记录关联所选格式。
- 便携包在精简 PATH 下验证启动、视频与音频下载、GUI 选择画质、解析缓存命中，以及 HLS/DASH 的实际输出。
- 覆盖临时标题变化、抖音搜索页编号优先级、旧版失败记录自动恢复、缓存过期与淘汰、过期地址刷新后保留已保存封面、筛选后画质选择保留及取消清理。
- Windows 测试验证虚拟环境启动器、真实 Python 进程及其子进程随引擎退出，避免遗留媒体工具。

## 平台实测

- 抖音：原失败链接取得真实标题、封面与 576p-MP4 元数据，媒体地址返回 HTTP 206 和有效视频字节。该视频约 144 分钟、约 1 GB，实测读取少量字节验证链接；完整下载流程使用测试媒体验证。
- Bilibili：公开视频取得真实标题、封面及四个实际格式（480p/360p，各含 H.264/H.265）。缓存重复提取耗时低于记录精度 0.1 毫秒。
- 其他平台共用格式描述、缓存与下载流程。中间生成任务地址不作为可下载画质，相关通道显示已经取得的实际媒体版本。
